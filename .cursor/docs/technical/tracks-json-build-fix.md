# Tracks JSON Build Fix

**Date**: 2024-12-XX  
**Status**: ✅ Resolved  
**Related Issue**: Vercel build failures when `tracks.json` is missing

## Problem

The music player component imports `tracks.json` as a static JSON file:

```typescript
import tracksData from '@/content/tracks/tracks.json';
```

This file is:

- Generated by a GitHub Action workflow (`.github/workflows/update-tracks.yml`)
- Gitignored (in `.gitignore`) because it's auto-generated
- Committed to the repo by the GitHub Action after generation

**Issue**: When Vercel builds the project, if the file doesn't exist in the repository (e.g., first build, or GitHub Action hasn't run yet), the build fails with:

```
Could not load /vercel/path0/src/content/tracks/tracks.json (imported by src/components/apps/music-player/context.tsx): ENOENT: no such file or directory
```

## Solution

The file is now properly tracked in the repository using `git update-index --skip-worktree`:

1. **Removed from `.gitignore`**: The file is tracked in the repo so Vercel builds always have it
2. **Skip worktree flag**: Local changes are ignored using `git update-index --skip-worktree`
3. **GitHub Action updates it**: The workflow commits updates to the tracked version

### How It Works

- **In the repo**: `tracks.json` is tracked and committed, so Vercel builds always have it
- **Locally**: Your changes to `tracks.json` are ignored by git (via `--skip-worktree` flag)
- **GitHub Action**: Can still commit updates because it runs in a fresh checkout without the flag
- **Result**: You can test locally with your own tracks, but the repo always has the generated version

### Setup Command

To set this up on a new machine or after cloning:

```bash
git update-index --skip-worktree src/content/tracks/tracks.json
```

To undo (if you want to track local changes again):

```bash
git update-index --no-skip-worktree src/content/tracks/tracks.json
```

## Better Solutions (Future Revisit)

### Option 1: Make Import Optional/Dynamic

- Use dynamic import with error handling
- Fallback to empty array if file doesn't exist
- Show user-friendly message when tracks are unavailable

### Option 2: Vercel Build Hook

- Use Vercel's build hooks to generate the file before build
- Requires Spotify API credentials in Vercel environment variables
- More reliable but adds complexity

### Option 3: Runtime Fetch Instead of Build-time Import

- Move from static import to runtime fetch
- Fetch from API endpoint or static file at runtime
- Better error handling and loading states
- More flexible but changes architecture

### Option 4: Always Commit Minimal File

- Keep a minimal `tracks.json` in the repo
- GitHub Action overwrites it when it runs
- Simplest but defeats purpose of gitignore

### Option 5: Astro Content Collections

- Use Astro's content collections system
- More integrated with Astro's build system
- Better type safety and validation
